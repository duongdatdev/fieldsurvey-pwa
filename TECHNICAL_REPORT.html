1. Executive Summary & Problem Statement

Field data collection in academic, governmental, and facility management settings routinely suffers from unstable or absent wireless connectivity (basements, remote structures, and concrete campus zones). Standard online-first web forms catastrophically drop form progress upon network disruptions. FieldSurvey PWA solves this problem through an offline-first Progressive Web Application integrated with Capacitor 8 for Android APK delivery, utilizing client-side IndexedDB persistence, a 5-strategy Service Worker, an autonomous idempotent Sync Queue, and a real Google Sheets / Google Apps Script serverless cloud database.

5. Service Worker Multi-Strategy Caching (sw.js)

The Service Worker architecture implements all five major caching strategies to guarantee zero downtime:

  • Cache-First (App Shell): Core assets (JS bundle, CSS, SVGs, web manifest) resolve directly from Cache Storage.
  • Network-First (Survey Definitions): Dynamically fetches the latest surveys catalog from cloud; falls back to cached definitions when offline.
  • Stale-While-Revalidate (Static Content): Serves cached copy instantly while revalidating and updating the cache in the background.
  • Network-Only (Submission API): Remote Google Apps Script POST calls bypass cache to prevent stale sync submissions.
  • Cache-Only (Emergency Fallback): Serves pre-cached offline.html if navigation fails during complete cold starts.

6. Offline Sync Queue & Idempotency Guarantee

To eliminate duplicate records caused by mobile connection dropouts, every response is generated with an RFC 4122 UUIDv4 on device:

  • Local-First Enqueue: When user taps Submit offline, response is saved to responses with status: "pending" and pushed to syncQueue.
  • Reconnection Dispatch: When networkService detects connectivity (Capacitor Network status change or window.online), syncManager.syncPendingResponses() triggers automatically.
  • Idempotency in Google Sheets: Before inserting rows, Code.gs scans Column A (responseId). If matching UUID exists, it returns { success: true, duplicate: true } without duplicate insertion.
